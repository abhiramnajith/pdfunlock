# Cross-Platform Builds + Hardened Auto-Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn PDFUnlock into a downloadable cross-platform app: build for macOS (arm64/x64), Linux (x64/arm64), and Windows (x64), published to GitHub Releases by a security-hardened CI/CD pipeline, under a MIT + Commons Clause license with custom branding.

**Architecture:** The existing Tauri v2 app already resolves a bundled `qpdf` sidecar next to its executable. This effort adds per-OS sidecar vendoring (mac dylibs, Linux `.so`+patchelf, Windows DLLs), per-platform Tauri config overrides, two hardened GitHub Actions workflows (`ci.yml` for tests/scanning, `release.yml` for the tagged matrix build), a license swap, and a custom icon.

**Tech Stack:** Tauri v2, Rust, React/TS, GitHub Actions, `tauri-apps/tauri-action`, `patchelf`, `install_name_tool`, qpdf, CodeQL, Dependabot.

## Global Constraints

- **Platforms:** macOS arm64 (`macos-14`) + x64 (`macos-13`); Linux x64 (`ubuntu-22.04`) + arm64 (`ubuntu-24.04-arm`); Windows x64 (`windows-latest`).
- **Unsigned:** no code signing/notarization; integrity via SHA-256 checksums + build-provenance attestations.
- **License:** MIT + Commons Clause. Copyright holder / Licensor: `abhiramnajith`. Software name in the notice: `PDFUnlock`.
- **Node is NOT on PATH.** Prefix npm/npx commands with:
  `export PATH="/Users/abhiramnajith/Library/Application Support/Zed/node/node-v24.11.0-darwin-arm64/bin:$PATH"`
- **CI security (every workflow):** top-level `permissions: contents: read`; jobs elevate only what they need. All third-party actions pinned to a full 40-char commit SHA (comment the version). `step-security/harden-runner` first in every job (audit mode). `actions/checkout` with `persist-credentials: false`. `concurrency` per workflow+ref. Explicit `timeout-minutes` per job. Pinned Rust toolchain + Node version. `npm ci` and `cargo ... --locked`. No `pull_request_target`. Release triggers only on `v*` tags; PR triggers get no secrets.
- **Testing reality:** only macOS builds are locally verifiable (dev machine is macOS). Linux/Windows builds are verified by the CI run. Existing suites (8 Rust integration tests + 4 vitest) must stay green.
- The app's productName/bundle is `pdfunlock`; lib crate is `pdfunlock_lib`; bundle identifier `com.pdfunlock.app`.

## Task 5: Linux qpdf vendor script + config

**Files:**
- Create: `scripts/vendor-qpdf-linux.sh`, `src-tauri/tauri.linux.conf.json`

**Interfaces:**
- Consumes: the dispatcher's `Linux) exec ... vendor-qpdf-linux.sh` branch (Task 4).
- Produces: `src-tauri/binaries/qpdf-<linux-triple>` + `*.so*` with `RPATH=$ORIGIN`.

> Not locally testable (dev machine is macOS). Written carefully; verified by the `release.yml` Linux job in Task 9. Keep the script self-contained and fail-loud.

- [ ] **Step 1: Write `scripts/vendor-qpdf-linux.sh`**

```bash
#!/usr/bin/env bash
# Vendor the system qpdf binary and its non-system .so deps into
# src-tauri/binaries/, setting RPATH=$ORIGIN so the binary finds its libs
# beside itself inside the bundle. Linux equivalent of vendor-qpdf-macos.sh.
set -euo pipefail
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DEST="$REPO_ROOT/src-tauri/binaries"

for tool in qpdf patchelf ldd; do
  command -v "$tool" >/dev/null 2>&1 || { echo "error: $tool not found (apt: qpdf patchelf)" >&2; exit 1; }
done

# Rust target triple for naming the externalBin (x86_64 or aarch64).
ARCH="$(uname -m)"
case "$ARCH" in
  x86_64)  TRIPLE="x86_64-unknown-linux-gnu" ;;
  aarch64) TRIPLE="aarch64-unknown-linux-gnu" ;;
  *) echo "error: unsupported arch $ARCH" >&2; exit 1 ;;
esac

rm -rf "$DEST"; mkdir -p "$DEST"
SRC_QPDF="$(command -v qpdf)"
cp "$SRC_QPDF" "$DEST/qpdf-$TRIPLE"
chmod u+w "$DEST/qpdf-$TRIPLE"

# Copy every non-system shared library qpdf depends on. Exclude the core
# system set that is always present on a target machine (libc, libm, dl,
# pthread, the dynamic loader, and the vdso).
ldd "$SRC_QPDF" | awk '/=>/ {print $3} !/=>/ && /^\// {print $1}' | while read -r lib; do
  [ -z "$lib" ] && continue
  base="$(basename "$lib")"
  case "$base" in
    libc.so*|libm.so*|libdl.so*|libpthread.so*|librt.so*|ld-linux*|linux-vdso*|libgcc_s.so*|libstdc++.so*) continue ;;
  esac
  if [ -f "$lib" ] && [ ! -f "$DEST/$base" ]; then
    cp "$lib" "$DEST/$base"
    chmod u+w "$DEST/$base"
    patchelf --set-rpath '$ORIGIN' "$DEST/$base"
  fi
done

# Point the qpdf binary at its co-located libs.
patchelf --set-rpath '$ORIGIN' "$DEST/qpdf-$TRIPLE"

echo "Vendored Linux qpdf sidecar into $DEST:"
ls -la "$DEST"
"$DEST/qpdf-$TRIPLE" --version
```

**Files:**

- Produces: `src-tauri/binaries/qpdf-x86_64-pc-windows-msvc.exe` + its DLLs.

- [ ] **Step 1: Write `scripts/vendor-qpdf-windows.sh`**

```bash
#!/usr/bin/env bash
# Download the official qpdf Windows build, verify its SHA-256, and copy
# qpdf.exe + its DLLs into src-tauri/binaries/. Windows resolves DLLs from the
# executable's own directory, so no rpath work is needed.
set -euo pipefail
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
DEST="$REPO_ROOT/src-tauri/binaries"

# Pin the exact qpdf Windows release and its published SHA-256. Bump both
# together when updating qpdf. Find checksums on the qpdf GitHub release page.
QPDF_VERSION="12.3.0"
QPDF_ZIP="qpdf-${QPDF_VERSION}-msvc64.zip"
QPDF_URL="https://github.com/qpdf/qpdf/releases/download/v${QPDF_VERSION}/${QPDF_ZIP}"
QPDF_SHA256="PUT_OFFICIAL_SHA256_HERE"   # from the qpdf release's checksums

rm -rf "$DEST"; mkdir -p "$DEST"
tmp="$(mktemp -d)"
curl -fsSL "$QPDF_URL" -o "$tmp/$QPDF_ZIP"
echo "$QPDF_SHA256  $tmp/$QPDF_ZIP" | sha256sum -c -
unzip -q "$tmp/$QPDF_ZIP" -d "$tmp/extracted"

# The msvc64 zip contains a bin/ with qpdf.exe and the DLLs it needs.
bindir="$(dirname "$(find "$tmp/extracted" -name qpdf.exe -print -quit)")"
cp "$bindir/qpdf.exe" "$DEST/qpdf-x86_64-pc-windows-msvc.exe"
cp "$bindir"/*.dll "$DEST"/ 2>/dev/null || true

rm -rf "$tmp"
echo "Vendored Windows qpdf sidecar into $DEST:"
ls -la "$DEST"
```

## Task 9: `release.yml` — matrix build, provenance, checksums (hardened)

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: the per-OS vendor scripts (Tasks 4–6) via `beforeBuildCommand`.
- Produces: a GitHub Release for the pushed `v*` tag with all installers, `SHA256SUMS`, and provenance attestations.

- [ ] **Step 1: Write `.github/workflows/release.yml`**

Fill pinned SHAs per the Task 8 pinning note.
```yaml
name: Release
on:
  push:
    tags: ["v*"]
permissions:
  contents: read
concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false
jobs:
  build:
    environment: release
    permissions:
      contents: write        # create the release / upload assets
      id-token: write         # provenance
      attestations: write     # provenance
    strategy:
      fail-fast: false
      matrix:
        include:
          - { os: macos-14,          rust_target: aarch64-apple-darwin,        args: "--target aarch64-apple-darwin" }
          - { os: macos-13,          rust_target: x86_64-apple-darwin,         args: "--target x86_64-apple-darwin" }
          - { os: ubuntu-22.04,      rust_target: x86_64-unknown-linux-gnu,    args: "" }
          - { os: ubuntu-24.04-arm,  rust_target: aarch64-unknown-linux-gnu,   args: "" }
          - { os: windows-latest,    rust_target: x86_64-pc-windows-msvc,      args: "" }
    runs-on: ${{ matrix.os }}
    timeout-minutes: 60
    steps:
      - uses: step-security/harden-runner@<SHA> # v2.x
        with: { egress-policy: audit }
      - uses: actions/checkout@<SHA> # v4.x
        with: { persist-credentials: false }
      - name: Install Linux build deps
        if: startsWith(matrix.os, 'ubuntu')
        run: |
          sudo apt-get update
          sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf qpdf file
      - name: Install macOS qpdf
        if: startsWith(matrix.os, 'macos')
        run: brew install qpdf
      # Windows qpdf is fetched by the vendor script (beforeBuildCommand).
      - uses: dtolnay/rust-toolchain@<SHA> # pin; toolchain 1.91.0
        with: { targets: ${{ matrix.rust_target }} }
      - uses: actions/setup-node@<SHA> # v4.x
        with: { node-version: "22", cache: "npm" }
      - run: npm ci
      - uses: tauri-apps/tauri-action@<SHA> # v0.5.x
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          tagName: ${{ github.ref_name }}
          releaseName: "PDFUnlock ${{ github.ref_name }}"
          releaseDraft: true
          prerelease: false
          args: ${{ matrix.args }}
      - name: Collect built bundles
        shell: bash
        run: |
          mkdir -p dist-artifacts
          find src-tauri/target -type f \( -name '*.dmg' -o -name '*.AppImage' -o -name '*.deb' -o -name '*.rpm' -o -name '*.msi' -o -name '*.exe' \) -path '*/bundle/*' -exec cp {} dist-artifacts/ \;
          ls -la dist-artifacts
      - name: Generate SHA-256 checksums
        shell: bash
        run: |
          cd dist-artifacts
          if command -v sha256sum >/dev/null; then sha256sum * > SHA256SUMS; else shasum -a 256 * > SHA256SUMS; fi
          cat SHA256SUMS
      - uses: actions/attest-build-provenance@<SHA> # v1.x
        with:
          subject-path: "dist-artifacts/*"
      - name: Upload checksums to the release
        uses: softprops/action-gh-release@<SHA> # v2.x
        with:
          tag_name: ${{ github.ref_name }}
          draft: true
          files: dist-artifacts/SHA256SUMS
```

> Notes for the implementer: `tauri-action` already creates the draft release and uploads the installers; the extra `action-gh-release` step only appends `SHA256SUMS` to the same draft tag. If `tauri-action` and `action-gh-release` conflict on the release, instead upload `SHA256SUMS` via `gh release upload "$GITHUB_REF_NAME" dist-artifacts/SHA256SUMS --clobber` in a `run:` step (with `GH_TOKEN`). Choose whichever the CI run shows works and note it.
